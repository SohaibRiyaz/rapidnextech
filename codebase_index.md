# RapidNexTech Codebase Index

Last updated: 2026-05-27
Project: RapidNexTech marketing site, CMS, blog, case studies, and industry landing pages
Framework: Next.js 14.2.16 App Router
Runtime target: Node 20.x

## Executive Summary

RapidNexTech is a Next.js App Router site with a Supabase-backed CMS for blog posts, projects, testimonials, partners, and comments. The public surface is primarily a conversion-focused marketing site: homepage, services, industry solutions, blog, case studies, about, careers, legal, and contact.

The build now succeeds after enabling the webpack build worker and clearing the generated `.next` cache. Current production build output shows 85 generated pages. The highest first-load JS surfaces are:

- `/blog/[slug]`: 260 kB first-load JS
- `/`: 224 kB first-load JS
- `/admin`: 224 kB first-load JS
- `/admin-login`: 192 kB first-load JS
- `/case-studies`: 164 kB first-load JS
- `/about`: 160 kB first-load JS
- `/contact`: 157 kB first-load JS

## Technology Stack

- Next.js 14.2.16 with App Router
- React 18.3.1
- TypeScript 5
- Tailwind CSS 3
- Radix UI primitives and shadcn-style UI components
- Framer Motion for animation-heavy sections
- Supabase for database, auth, and storage
- Resend for contact/intent email notifications
- Hugging Face image generation endpoint for blog image generation
- `next/font/google` for Inter, Space Grotesk, and landing-page display fonts

## Repository Shape

- `app/`: App Router routes, API endpoints, metadata, sitemap, robots
- `components/`: shared UI, layout, public marketing sections, admin modules, solution sections
- `context/`: theme and admin auth contexts
- `hooks/`: client hooks
- `lib/`: CMS data layer, Supabase client/types, site URL helpers, service data, utility modules
- `public/`: static images, favicons, SVGs, Open Graph image, illustrations
- `scripts/`: Supabase SQL migrations and data maintenance scripts
- `docs/`: database/migration docs

## Route Inventory

### Public Static/Marketing

- `/`: homepage. Server route rendering client sections. Uses hero, partner carousel, stats, services bento, featured work, testimonials, process, CTA.
- `/about`: server page wrapping `AboutClient`, with page metadata and JSON-LD.
- `/services`: client-heavy services index with Framer Motion and service category cards.
- `/services/[slug]`: statically generated service detail pages from `lib/services-data.ts`.
- `/solutions/aesthetic-clinics`: dynamic because it reads search params for auto-opening demo UI.
- `/solutions/real-estate`: static industry landing page.
- `/solutions/diet-nutrition`: static industry landing page.
- `/solutions/never-miss-a-call`: static home-services voice landing page.
- `/solutions/never-miss-a-medspa-call`: static med-spa voice landing page.
- `/case-studies`: server page fetching published Supabase projects, rendered through `PortfolioClient`.
- `/case-studies/[slug]`: SSG project detail pages with dynamic params enabled for new projects.
- `/blog`: server page fetching published Supabase blog list, rendered through `BlogClient`.
- `/blog/[slug]`: SSG blog detail pages with dynamic params enabled for new posts.
- `/contact`: server page wrapping `ContactClient` in Suspense because the client reads search params.
- `/careers`: static careers page with SVG-heavy sections.
- `/privacy-policy`, `/terms-of-service`: static legal pages.
- `/privacy`, `/terms`: redirect aliases.

### Admin

- `/admin-login`: client login page. Wrapped in route-level `AuthProvider`; noindex.
- `/admin`: client admin dashboard. Wrapped in route-level `AuthProvider`; noindex.

### API

- `/api/contact`: sends contact form email through Resend.
- `/api/stripe-intent`: sends Stripe/payment-intent email through Resend helper.
- `/api/exchange-rates`: fetches GBP/QAR exchange rates with 1-hour revalidation.
- `/api/ai-blog-image`: generates an image via Hugging Face and uploads it to Supabase Storage.

### SEO System Routes

- `/robots.txt`: generated by `app/robots.ts`.
- `/sitemap.xml`: generated by `app/sitemap.ts`; currently dynamic because it fetches fresh Supabase blog/project rows and calls `unstable_noStore()`.
- `/manifest.json`: app manifest route.

## Data Layer

Primary CMS entrypoint: `lib/supabase-cms.ts`.

CMS classes:

- `PortfolioCMS`: projects, featured projects, publishing flags, slug fallback lookup.
- `BlogCMS`: blog lists, full post by id/slug, related posts, search/tag filters, publish toggles.
- `ReviewsCMS`: testimonials/reviews and featured flags.
- `PartnersCMS`: trusted partner logos.
- `BlogCommentsCMS`: approved public comments plus admin moderation.
- `StorageCMS`: Supabase Storage image upload helper.

Important current state:

- Blog public/admin list queries avoid `content`, which is good for payload size.
- Project public list queries still use `select("*")`, so case-study pages can pull more data than cards need.
- Fallback slug matching for projects/blog posts fetches all published rows when exact slug fails. This helps legacy content, but it is a performance fallback and should be cleaned up once all slugs are canonical.
- The Supabase browser client is imported in shared CMS modules, so client components that import CMS functions can ship Supabase client code to the browser.

## Performance Baseline

Build metrics from clean `npm run build:only`:

- 85 generated pages.
- Root shared first-load JS: 87.5 kB.
- Homepage first-load JS: 224 kB.
- Blog detail first-load JS: 260 kB.
- Contact first-load JS: 157 kB.
- Services detail first-load JS: 152 kB.
- Best-performing solution pages: real-estate/diet-nutrition at 116 kB.

Main performance drivers:

- Heavy global client layout: header, footer, theme context, top loader, WhatsApp widget.
- Many components marked `"use client"`: 145 of 240 TS/TSX source files.
- Framer Motion used across homepage, services, about, blog, case studies, solutions, and admin.
- Blog detail client bundle includes markdown rendering, related posts, social share, comments, and image handling.
- Homepage still fetches featured work and partner logos client-side instead of passing server-fetched initial data.
- `images.unoptimized: true` disables Next image optimization globally. This may be intentional for static export, but it limits LCP/image improvements on server deployments.
- Several public image usages still use raw `<img>` where `next/image` could improve sizing and lazy loading.

## Build And Quality Status

Successful:

- `npm run build:only` passes after enabling `experimental.webpackBuildWorker`.

Still failing:

- `npm run lint` fails with many existing errors: unused imports/vars, `any`, unescaped entities, missing hook deps, and `<img>` warnings.
- TypeScript is configured with `ignoreBuildErrors: true`, and production builds skip type validation.
- ESLint is configured with `ignoreDuringBuilds: true`, so production builds skip lint validation.

Important build note:

- `package.json` declares Node `20.x`, but the current shell reports Node `22.15.1`. Build instability was observed under Node 22 until `.next` was cleaned and `webpackBuildWorker` was enabled. Use Node 20 for consistent CI/local parity.
